# 日本の水路の交差点 検出 設計メモ

## 目的

LT「同じ番号の道が、自分自身と交差している」(`../route153-investigation`)のおまけで扱った
玉川上水 × 残堀川 のような「水路どうしの交差」を、日本全国について OSM から特定する。
趣味。用途は未定で、まずは表と OSM リンクで眺められればよい。

## ゴール / 非ゴール

- ゴール: 全国の水路の交差点を、立体・平面を問わず列挙した表(Markdown)と、元データの JSON
- ゴール: 関東で 玉川上水 × 残堀川(way 60964194 × way 1117757672 付近、35.72734, 139.38766)が出ること
- 非ゴール: 地図表示、現地・航空写真での確認、OSM 以外のデータとの突き合わせ
- 失敗とみなすもの: 合流点・分流点が「交差」に大量に混ざること

## 仮説(ユーザー)

自然の川どうしは交差しないはず。`waterway=river` × `river` の交差が出たら、データの誤りか
人工河川(放水路など)の river タグを疑う。結果の集計でこの仮説を確かめる。

## 対象データ

- `~/y-junctions-data/osm/` の Geofabrik 8地方: hokkaido, tohoku, kanto, chubu, kansai, chugoku, shikoku, kyushu
- 線の水路すべて: `waterway=river|stream|canal|drain|ditch`(用水路どうしも数える)
  - (私の判断)`tidal_channel` も含める。`riverbank`・`dam`・`weir` など線の水路でないものは外す

## 交差の定義と分類

2本の別の水路 way の線が交わる点を候補とし、次で分ける。

| 分類 | 条件 | 扱い |
|---|---|---|
| 立体交差(記入あり) | 交点でノードを共有せず、どちらかに `tunnel` / `bridge` があるか `layer` が異なる | 交差 |
| 立体交差(記入なし) | 交点でノードを共有せず、上下の記入もない | 交差(書き忘れ・誤りの可能性として列で区別) |
| 共有ノードで交差 | 共有ノードに入る線 2・出る線 2 | 交差 |
| 合流 | 入る線 2以上・出る線 1 | 除外 |
| 分流 | 入る線 1・出る線 2以上 | 除外 |

- 入る/出るは OSM の水路が流下方向に描かれる決まりを使う(way の終点=入る、始点=出る、途中の点=入1出1)
- 共有ノードでの「入2出2」には「合流してすぐ分流」も含まれ得る。(私の判断)交差として残し、
  入ってきた各線が対向方向へ抜けているか(方位角で 180±35°、153号調査と同じ許容)を「直進」列で示す
- 線が重なって交点が点にならないもの(同じ水路の重複トレース等)は除外し、件数だけ記録する

## 作り方(採用: 案B)

検討した案:

- A. 標準 Python のみ(selfcross.py の延長): 依存なしだが、非共有の線分交差判定を自前で書く必要があり、全国規模で速度・正しさの担保が重い
- **B. osmium で waterway に絞り、pyosmium + shapely(STRtree)で判定** ← 採用。難所の幾何交差をライブラリに任せられる
- C. PostGIS: 問い合わせの反復には強いが、趣味の初手には準備が重い

手順:

1. `osmium tags-filter <region>.osm.pbf w/waterway -o data/<region>_waterway.osm.pbf`
2. `scripts/` の Python 1本で、way を LineString 化 → STRtree で交わる組 → 上の分類 → JSON
3. 8地方を処理し、地方の境界で重複した交点はノードID(共有の場合)または座標(非共有の場合)で1件にまとめる
4. 表を Markdown で出力

依存は `uv` で管理(pyosmium, shapely)。

## 表の列

\#, 分類, 水路A(name, waterway, tunnel/bridge/layer), 水路B(同), 座標, 地方, 直進(共有ノードのみ),
OSM リンク(両 way と `#map=19/lat/lon`)

加えて、分類ごとの件数と、waterway の種類の組み合わせ(river×river、canal×stream …)ごとの件数を出す。

## 実装者に任せること

- 全国の件数が多すぎて表が読めない場合の分け方(地方別ファイル、種類別など)
- 処理速度の工夫
